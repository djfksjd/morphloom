# 구성 요소 제작 플랫폼 — 요구사항과 검증 범위

2026-10-02 사용자 요구사항을 기준으로 한다. 기존 품질·하위 호환·회귀 게이트를 유지한다.
완성 단일 메시가 아니라 의미 구조와 미세 요소를 생성·편집·분리·재사용하는 오픈소스 엔진이 목표다.
전 분야 지원 완료와 새 분야를 수용할 아키텍처를 구분한다.

## 첫 수직 슬라이스

제품·하드서피스 우선 대신 깃털이 있는 새를 먼저 구현한다.
순서: 독립 기관 → 깃털 분포와 ID → 한 장 편집·분리·복원 → 그룹 grooming과 override
→ LOD·성능·납품 → 털 사례로 일반화. 실제 코드·시연·원본 명세·납품·재열기 증거로 판정한다.

필수 합격 시나리오:

- 왼쪽 눈만 이동·분리·복원하며 다른 기관을 보존한다.
- 상부 부리만 수정하며 하부 부리와 나머지 구조를 보존한다.
- 날개깃 한 장의 길이·곡률·재질을 수정한다.
- 그 깃털만 좌표계·재질을 포함한 독립 파일로 내보내고 Blender에서 재열어 확인한다.
- 그룹 수정 시 개별 override의 명시된 정책을 지킨다.
- 저장·재열기·undo/redo 후 ID와 수정 내용을 보존한다.
- 저해상도 표시 전환이 원본 편집 데이터를 지우지 않는다.
- 털 한 가닥에도 같은 선택·편집·추출 원칙을 적용한다.
- 요소·삼각형·draw call·메모리·생성 시간·선택 응답·파일 크기를 환경과 함께 기록한다.
- 지원 규모를 실제로 시험하며 자원 예산 초과는 명시적으로 차단한다.

## 공통 요소 계약

asset → anatomical/functional part → surface region → element group → individual element
→ optional sub-element. 편집 요소마다 안정 ID와 소유 관계를 둔다. 생성 규칙·파라미터,
로컬 좌표와 부착 위치, 형태·재질·변형, observed/inferred/authored 및 근거,
override, 표시·선택·잠금 상태를 관리한다.

같은 입력·seed는 같은 ID를 만든다. 국부 수정은 무관한 ID를 변경하지 않는다.
개수 변경·대응 불가능 시 추가·삭제·재매핑을 명시한다. 의미상 편집 가능성과 Object3D 수는
독립이다. 인스턴싱·곡선 버퍼·공유 기하·공간 인덱스를 사용해도 원본 의미 구조를 유지한다.
원본과 표시·결합·납품 파생 데이터를 구분한다.

단일 선택·숨김·삭제·복제·위치/방향/길이/두께/곡률/재질 수정·독립 추출,
조건/영역/브러시 집합 선택, 공유 원형 편집과 개별 override를 구분한다.
계층 트리·화면 클릭·isolate/hide·원래 위치를 유지한 explode·독립 에셋 추출·복원·선택 저장을
제공한다. explode만으로 독립 편집·파일 분리가 구현됐다고 표시하지 않는다.

## 깃털과 털

깃털은 root/tip·부착 방향·길이/폭/두께·깃대 곡률/테이퍼·좌우 깃판/비대칭·비틀림/굽힘/끝,
색/무늬/광택/거칠기·깃가지 방향/간격/길이·겹침/간섭을 표현한다.
몸깃·날개깃·꼬리깃·솜깃의 구조와 분포를 구분한다. 날개 운동 부착 추종·펼침/겹침과
주요 관통 검사를 추가한다. A 합성 표면/카드, B 개별 형태, C 깃대/깃판/주요 깃가지,
D 선택적 깃가지/깃소지를 구분한다. 모든 초미세 구조를 항상 메시화하지 않고 선택 고해상도와
자원 예산을 적용한다. ID와 편집 데이터는 LOD 사이에 보존한다.

털은 root와 부착 표면이 있는 strand 또는 명시적 대체 표현이다. 성장 흐름·길이·뿌리/끝 두께,
곡률/꼬임/컬·밀도/마스크·clumping/breakup·색/재질·부위별 grooming을 둔다.
guide로 무리를 제어해도 개별 ID/override를 보존한다. comb·cut/length·bend/curl·density·clump
·paint mask·isolate/extract를 단계적으로 구현한다. 눈/입 보호 영역과 피부 관통을 관리한다.
고해상도 strand·curve/tube·card별 품질/성능/내보내기 차이를 명시한다.

## LLM과 엔진

LLM은 의미 구조·부위별 형태/분포·근거/불확실성·선언형 편집 요청을 작성한다.
엔진은 검증·반복 생성·부착/곡률/분포/간섭·ID/override·LOD/렌더/납품·품질 검사를 담당한다.
좌표를 LLM이 하나씩 쓰게 하지 않는다. 기존 IR을 유지하면서 필요한 선언형 계약을 추가한다.
작은 유효 명세·템플릿·기본값·스키마·구조화 오류와 수정 예제를 제공한다.
임의 코드 생성 없이 생성/수정하는 경로를 우선하며 모델과 엔진 성능을 별도 평가한다.

## 납품과 공개

절차 원본/IR·curve/strand·instance·baked mesh/card 및 DCC 편집 범위를 구분한다.
GLB가 groom/curve/modifier 의미를 보존한다고 가정하지 않는다. 원본 프로젝트와 호환 메시를
함께 제공하고 보존/근사/손실·오차·복원 가능 범위를 기록한다. 파일 확장자가 있다는 것만으로
호환성을 인정하지 않는다. 핵심 코드를 오픈소스로 제공하며 비공개 서비스 의존을 기본값으로
삼지 않는다. 샘플/자료/텍스처의 재배포 권한을 확인한다. authored 예제는 실측 해부학이 아니다.

## 기계 및 전 분야 확장

공통 코어 위에 Domain Pack을 연결한다. 기어/축/베어링/전동체/케이지/씰/체결 부품 및 하위
feature ID, 조립 관계·회전축·좌표·치수 재생성을 지원하도록 확장한다.
기어의 모듈/잇수/압력각/치폭과 베어링 구조를 검증한다. 연결된 tooth feature 추출과 실제
분리 조립 부품을 구분한다. 베어링 볼 한 개의 수정·추출·재열기를 추가 합격 사례로 둔다.
시각화·운동학·물리·제조 검증을 구분하고 미관측 내부는 inferred/authored로 둔다.

생물/식생, 기계/로봇/전자, 건축/토목/도시, 제품/패션, 게임/영화/VFX, 의료/과학,
지형/GIS/디지털 트윈, 제조, XR 등은 열린 확장 지도다. 고정 enum/키워드 분기만으로 제한하지
않는다. Pack 계약은 대상/작업·입력/표현·연산·파라미터/단위/제약·스키마·편집/검사 UI,
품질/지원 수준·입출력 어댑터·의존/버전·비용/자원·예제/conformance를 선언한다.
버전 호환·오류 격리를 제공하고 등록만으로 검증 완료 표시하지 않는다.

요청→capability→구현→실행 계획→검증→납품으로 연결한다. 복합 분야도 같은 프로젝트에서
조합한다. 필수 기능 부족은 명시하고 대체/정보 손실을 설명한다. mesh/subdivision,
curve/strand/spline, NURBS/solid/BREP, point cloud, voxel/volume/field, terrain/좌표,
skeleton/deformation/time, assembly/constraint/procedural graph, instance를 원본/파생 관계로
관리한다. 네이티브·외부 커널·참조·변환 지원을 구분한다.

단위·축·handedness·로컬/월드·지리 좌표/정밀도·기준점·시간/샘플링·물리량/허용오차·의미
충돌을 검출하고 자동 추측으로 합치지 않는다. appearance와 물리 속성을 별도 관리한다.
GLB/USD/STEP/BREP/IFC 및 전문 형식은 어댑터별 읽기/쓰기/의미 보존/재열기로 판정한다.
현재 선택한 표현/capability에 맞는 UI 도구를 노출하고 미지원 도구는 이유를 설명한다.

분야×작업×표현×대상 도구의 planned/experimental/preview-verified/editing-verified/
delivery-verified/blocked 상태마다 현재 버전의 증거를 연결한다. 의료/구조/전기/제조는
시각화와 전문 승인 능력을 구분한다. 한 분야의 성공을 다른 분야 검증에 재사용하지 않는다.

확장성 합격: 코어 복제 없이 Pack 추가, 실제 생성/편집/검사/납품, 두 분야 capability 조합,
단위/좌표/표현 충돌 검출, 미지원 조합 거부, 실패 격리, SDK/최소 예제/스키마/conformance 제공.
새 수직 슬라이스에서 검증된 공통 기능만 코어로 추출한다. 전 분야를 동시에 얕게 구현하지 않는다.

## 개발 방식

Supervisor가 파일 확인·제안 검토·최소 적용·실행 검증을 맡고 UNI_AI API가 분석·초안·리뷰를
맡는다. API 응답은 실행 증거가 아니다. gateway와 사용량은 Raptor의 UNI_AI_WORKFLOW 절차를
따른다. 키는 Raptor의 ignored .env에서 필요한 항목만 읽으며 저장소나 프롬프트에 복사하지 않는다.
Ruflo 전체 도입은 보류한다. 호스트 플랜 사용량 0이나 API 비용 절감을 보장하지 않는다.
