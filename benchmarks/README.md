# Benchmark policy

`llm-browser-routing-latest.json` records an authenticated three-provider web trial performed in the user's Chrome window through the Chrome extension and Playwright. ChatGPT Free-default, Claude Fable 5 high, and Gemini Flash received the same four hash-bound fan photos and the same final visual-plan prompt. The engine accepts ChatGPT's plan after four source-kind corrections proven by exact image hashes; it blocks Claude and Gemini because visible repeated parts were grouped as non-editable arrays. The run proves provider-boundary validation and safe metadata recovery only. It did not generate three provider GLBs, did not identify the exact ChatGPT model, and does not support a lowest-model or superiority claim.

`img2threejs-abo-fan-cli-latest.json` records the isolated same-input, low-model CLI execution audit. The generated factory could not export unchanged because its `procedural://` references were not texture payloads and its runtime metadata was circular. A separately disclosed compatibility harness recovered an inspectable GLB without adding geometry: 8 meshes and 17 nodes versus Morphloom's 101 meshes and 102 nodes. `abo-fan-neutral-comparison-latest.json` proves both recovered GLBs were reopened by Blender and rendered from the same front/rear/iso protocol. `abo-fan-low-model-blind-latest.json` binds the four input photos and anonymous candidate renders by hash and records order-reversed Codex Mini and Claude Haiku ratings. All four ratings prefer Morphloom on this fan, but the report remains claim-blocked because it is one case, two model families, one rendered candidate view, and not a five-person panel. These audits do not replace calibrated matched-reference scoring or the production-dominance gate.

`npm run benchmark:dominance` is the only gate allowed to make an all-domain superiority claim. It requires at least three independent, same-input cases in each of architecture, industrial design, electronics assembly, animation, game, 3D print, and surface work. Repeated input fingerprints, candidate files, or release receipts do not count as extra cases. The visual report must bind the exact locked input and both engine revisions. Every Morphloom case must pass deterministic rebuild, browser GLB round-trip, production release, and native Blender reopen; game also needs Unity, Unreal, or Godot evidence, while 3D print needs a real slicer reopen. Every case must independently pass the balanced blind visual winner contract and may not regress against img2threejs on delivery score. Missing competitor evidence is a blocker, not a win. The latest honest status is written to `production-dominance-latest.json`.

The external ABO pilot validates 3/3 corpus cases and 18 assets. The semantic lamp passes its ground-truth shape gate. A harder semantic fan pilot exports 101 editable parts and a deterministic Khronos-valid GLB, while honestly blocking release on four-view silhouette, ground-truth surface fidelity, PBR provenance, and hidden interfaces. Its current 4,096-point shape result is 4.15% maximum dimension error, 0.0560 RMS Chamfer, 0.1157 P95 distance, and 54.15% minimum coverage.

Reference-derived material maps are admitted only from dense, stationary surface evidence. The masked extractor removes studio background, erodes silhouette boundaries, binds the selected pixels to their source SHA-256, and records per-channel provenance for base colour, normal, roughness, and metallic response. Sparse product silhouettes fail closed: the fan photos contain grilles, blades, gaps, and part boundaries rather than a reusable material close-up, so the engine rejects them instead of repeating those structures as fake micro-texture. A source-bound normal or roughness map does not prove calibrated metallic response or BRDF parameters.

`npm run benchmark` measures properties that can be reproduced from geometry and material state: triangles, named parts, category coverage, watertight components, boundary/non-manifold edges, degenerate triangles, declared modeling operations, connected ports/conductors, dangling ends, owning-component port placement, terminal-center drift, physical pin labels, conductor gauges, verification records, pending bench gates, live endpoint anchoring, authored PBR finishes, micro-normal/roughness coverage, anisotropy, clearcoat, and transmission.

`npm run quality:gate` recompiles product, architecture, service-assembly, character, 3D-print, and surface cases twice, compares deterministic fingerprints, applies evidence and micro-surface thresholds, and writes `quality-latest.json`. It then runs the eight-stage Fidelity Contract benchmark and writes `competitive-latest.json`. Each locked case declares whether the correct outcome is release or block. The overall rate requires both technical integrity and the correct decision; expected rejections count only when their named blocker is observed. Model/browser release rates use only release-intended cases, while expected rejections have a separate safety rate. These locked technical contracts are not independent blind-comparison cases and therefore do not satisfy the superiority claim gate by themselves.

The current suite locks nine decisions: six release-intended contracts plus three evidence-limited rejections. Domain readiness is not one shared beauty score:

- architecture requires a verified plan footprint, closed shells, evidence ≥85, and ≥80% micro-normal coverage;
- industrial design requires closed topology, evidence ≥80, ≥95% UV coverage, and ≥75% micro-normal coverage;
- electronics assembly requires closed topology, a zero-error part/pin/conductor graph, 100% physical-pin/gauge/verification documentation, live moving-part anchors, at most 0.05 mm endpoint drift, evidence ≥90, UV/normals, and ≥75% micro-normal coverage. Digital connectivity and physical-production evidence are separate blocking checks;
- animation requires closed skinned LOD meshes, at least 45 real bones, 30 named finger bones with actually weighted hand vertices, at least 16 finger tracks, normalized ≤4-influence weights, measured non-zero joint deformation, UVs, all 22 semantic delivery clips with at least 180 tracks, actual motion on every track, closed loop seams, in-place locomotion, and exact GLB clip/binding/metadata preservation;
- game requires the delivered triangle budget, no non-manifold or degenerate geometry, UVs, normals, a real skeleton, all 22 locomotion/turn/stance/airborne/gesture/interaction clips, actual motion and loop/root-motion contracts, an actual skinned LOD1, collision primitives, and PBR surfaces;
- surface requires closed topology, source evidence, finite non-degenerate UVs, unit normals, recomputed delivered-vertex relief, coarse and fine aggregate structure, and complete normal/roughness PBR response;
- 3D print requires a closed positive-volume mesh, explicit millimetres, an IR-declared minimum feature and global `2V/A` screening value of at least 0.8 mm, a completed bounded inward-ray local wall audit with every sampled wall at least 0.8 mm, and measured generic 45° overhang area. The default local audit caps work before large allocations at 256 meshes and 500,000 collected triangles, then at 96 rays per mesh and 24 million triangle tests; missing hits, zero-volume components, and exhausted budgets block release. Printer-specific orientation and support generation remain downstream process checks.

A browser proof requires the viewer to export and reopen the actual GLB. The verifier waits for asynchronous reference projection, then binds the receipt to the normalized input fingerprint, the exact pre-export build fingerprint, the scene-fingerprint revision, and the exact scene fingerprint after deterministic normal/tangent preparation. Scene identity includes actual inspectable texture pixels, glTF-visible sampler/UV state, and scalar/optical material semantics. GPU upload alignment and lazily derived texture matrices are excluded because they are not interchange appearance semantics. Unsupported texture mapping, pixel type/format, anisotropy, premultiplied alpha, transform centre/manual matrix, or mip-filter state fail closed before export. All values are compared with a current repeated build; hexadecimal shape alone is not evidence. Duplicate asset ids, a dirty browser console, more than 0.1 mm bounds drift, less than 95% named-node coverage, missing morph-, texture-, or material-payload parity, uninspectable texture pixels, or glTF-incompatible material semantics fail closed. A fixed score, stale compiler/fingerprint revision, stale input/build/prepared-scene proof, or download click is not evidence.

It does not convert triangle count into a beauty score. Reference fidelity needs the same admitted images and camera calibration. Morphloom computes same-canvas reference/render silhouette IoU, interior pixel similarity, feature-region scores, material response, and frame fingerprints. The strict multi-view path downsamples the complete shared canvas and never fits each foreground independently, so offset, scale, framing, pose, and proportion errors remain measurable. A winner claim is refused unless both engines use the locked identical input, matched calibrated cameras, one canonical canvas/pixel-ratio/color/tone/light protocol, actual browser WebGL captures with hash-bound receipts, declared critical regions, and at least five unique blind raters with balanced presentation order. Automatic metrics alone may report a lead, never superiority. Capture sets run through `npm run benchmark:visual-set`; the manifest format and fail-closed release flag are documented in [`../docs/VISUAL_CAPTURE_SET.md`](../docs/VISUAL_CAPTURE_SET.md). See also [`../docs/COMPETITIVE_BENCHMARK.md`](../docs/COMPETITIVE_BENCHMARK.md).

The gate also refuses reused reference or render bytes, a structural scene fingerprint that changes across views, a screenshot hash passed off as structural scene evidence, a reused or hash-mismatched browser capture receipt, a receipt whose canvas or render protocol differs, evidence paths escaping the manifest directory, different feature rectangles between candidates, renamed copies of one rectangle, blank/tiny foreground evidence, byte-identical reference/render pixels, and a high average that hides a failed calibrated view. Every calibrated view for one candidate must come from the same independently fingerprinted compiled scene. Industrial design needs at least two distinct views and three distinct, identical critical regions per view; architecture, character, and surface cases require their domain minimums. `talon-visual-broadside-latest.json` is intentionally `unproven`: its one real broadside capture is useful regression evidence but cannot satisfy the two-view and blind-panel claim contract.

`npm run benchmark:neutral-render` removes viewer composition as a confounder by importing an actual GLB into Blender 5.2.1 LTS, fitting the broadside envelope to exactly 2.0 units, and using a locked square Eevee camera/light/color-management protocol. Protocol v2 also measures the rendered alpha silhouette and fails when less than 8 pixels of clear frame remain, preventing the former wide-canvas top/bottom clipping from masquerading as a fair comparison. `npm run benchmark:neutral-audit` recalculates the GLB and PNG SHA-256 values, confines artifacts beside each receipt, requires identical settings for both candidates, and requires one stable GLB with distinct front/rear/iso renders. Passing this audit proves fair render conditions only; calibrated references and blind ratings are still required for a perceptual winner claim.

`npm run benchmark:static-delivery` reads the source triangle count and browser loader receipts from the real downloaded asset pack, then binds its OBJ/STL/PLY/USDZ bytes to SHA-256 values, the current GLB compiler revision, static-delivery revision, and asset id. Packed bytes must exactly match the files independently imported by Blender 5.2.1. OBJ/PLY coordinates remain metres and source Y-up; STL coordinates are multiplied by 1,000 and rotated to printer Z-up. All three formats need exact triangle parity and at most 0.1 mm axis-normalized envelope drift. Apple's `usdchecker` must accept the repaired USDZ. This proves static-mesh and Apple AR handoff only. It does not turn OBJ/STL into STEP/BREP or preserve PBR, rigging, and animation outside GLB.

`npm run benchmark:blender-cross-domain-edit` imports the five signed architecture, industrial-design, electronics, character, and surface GLBs into Blender, edits one stable-ID target only, exports it, reopens it twice, and compares the delivered result with the original source. The locked edits are a window width change, knife pommel-gem move, USB-C port move, bounded hair move, and bounded asphalt relief change. The audit requires every non-target mesh to retain its world-space geometry, topology, UVs, and material payload; character skin weights, inverse-bind matrices, and animation channels must also survive. Blender-renamed or degraded glTF material state is restored only when it can be matched to the original stable node ID and primitive index. Passing proves isolated DCC editability for these five cases, not unrestricted semantic editing of arbitrary assets.

All native-tool reports are revision-bound. A report generated by an older compiler remains useful historical evidence but is rejected by the competitive gate until the same artifact is regenerated and reopened against the current compiler revision. The current static-delivery and PrusaSlicer receipts are bound to compiler 0.31.0; future compiler changes automatically make them stale again.

`npm run benchmark:godot-cross-domain -- <fixture-directory>` imports the five signed deterministic GLBs with the official Godot 4.7.2 editor, then opens each imported `PackedScene` in headless Godot and compares mesh, material, texture, skin, bone, morph, animation, and world-space envelope counts against the source bytes. For the asphalt case it also recomputes RMS and peak-to-valley relief from upward-facing delivered vertices on both sides and blocks more than 0.02 mm of native-import drift. The report rejects stale receipts and binds the exact Godot binary SHA-256. It proves import integrity, not gameplay, physics, performance, or final-art approval.

`npm run benchmark:prusaslicer -- <fixture-directory>` reopens the signed Z-up millimetre STL in PrusaSlicer 2.9.6, requires one manifold positive-volume part, compares native facet and bounds output with the binary STL, and generates a bounded coarse G-code proof. The generic virtual-bed profile is deliberately not represented as a production printer profile.

A digitally connected harness is not automatically production-ready. Any `bench-required` conductor, pending bench check, or inferred component keeps the physical-release flag false even when every 3D endpoint is snapped.

The Spider-Man single-image case therefore records two separate results: the compiled asset can pass closed-topology and editable-part gates while the one-view likeness gate remains blocked. `gamePrevisBaseReady` must never be presented as `productionLikenessReady`.

The Galaxy Z Fold8 exterior case records Samsung's published folded and unfolded envelopes separately from the compiled camera-bump envelope. Official dimensions, screen ratios, camera count, material families, and accessory-placement drawing values are `datasheet`; unpublished ring diameters, button protrusion, port pitch, and crease response remain `estimated` or `inferred`. Its exterior-only scope must not be reported as an internal engineering model.

When a new baseline is added, store its public URL, version, visible metrics, and the date observed. Never copy a proprietary asset into this directory.

`talon-same-reference-latest.json` is the first real same-input render case. It keeps the public URL and measured delivery facts only; the third-party reference bitmap and competitor render are not redistributed. The result deliberately separates photographic likeness from editable delivery quality.

`asphalt-reference-latest.json` records the local-photo surface path without redistributing the bitmap. The v3 gate converts the admitted pixels to linear light, applies bounded broad-illumination removal, and binds that same corrected evidence to the embedded fine/medium/coarse height field plus projected albedo, normal, and roughness response. It separately blocks weak signal, missing scales, periodic substitutes, implausible normal response, and flat roughness before geometry compilation. Closed topology and exact GLB reopen remain independent delivery gates. A passing evidence score does not promote image-derived relief to measured height; site-specific absolute height still needs calibration or scan evidence.

`npm run benchmark:asphalt-same-input` consumes the map receipt produced by the pinned img2threejs extractor and runs Morphloom against the exact same asphalt bytes, places both map sets on equal closed carriers, exports canonical GLBs twice, reopens the delivered vertices independently, and records source-colour error plus real top-surface relief in `asphalt-same-input-latest.json`. The current case finds 4.45 mm of delivered Morphloom relief versus a flat img2threejs GLB, while Morphloom's mean albedo luminance differs from the corrected source by 0.00073 versus 0.45065. Locked Blender 5.2.1 top and grazing renders pass the same protocol. This is a technical win for one surface case; the perceptual winner remains pending until the local images can be sent to an approved balanced blind panel.
