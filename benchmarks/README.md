# Benchmark policy

`npm run benchmark` measures properties that can be reproduced from geometry and material state: triangles, named parts, category coverage, watertight components, boundary/non-manifold edges, degenerate triangles, declared modeling operations, connected ports/conductors, dangling ends, owning-component port placement, terminal-center drift, physical pin labels, conductor gauges, verification records, pending bench gates, live endpoint anchoring, authored PBR finishes, micro-normal/roughness coverage, anisotropy, clearcoat, and transmission.

`npm run quality:gate` recompiles product, architecture, service-assembly, and character cases twice, compares deterministic fingerprints, applies evidence and micro-surface thresholds, and writes `quality-latest.json`. It then runs the eight-stage Fidelity Contract benchmark and writes `competitive-latest.json`. Each locked case declares whether the correct outcome is release or block. The overall rate requires both technical integrity and the correct decision; expected rejections count only when their named blocker is observed. Model/browser release rates use only release-intended cases, while expected rejections have a separate safety rate.

The current suite locks eight decisions: five release-intended contracts (industrial design, measured architecture, animation, game, and 3D print) plus three evidence-limited rejections. Domain readiness is not one shared beauty score:

- architecture requires a verified plan footprint, closed shells, evidence ≥85, and ≥80% micro-normal coverage;
- industrial design requires closed topology, evidence ≥80, ≥95% UV coverage, and ≥75% micro-normal coverage;
- animation requires closed skinned LOD meshes, at least 45 real bones, 30 named finger bones with actually weighted hand vertices, at least 16 finger tracks, normalized ≤4-influence weights, measured non-zero joint deformation, UVs, all 22 semantic delivery clips with at least 180 tracks, actual motion on every track, closed loop seams, in-place locomotion, and exact GLB clip/binding/metadata preservation;
- game requires the delivered triangle budget, no non-manifold or degenerate geometry, UVs, normals, a real skeleton, all 22 locomotion/turn/stance/airborne/gesture/interaction clips, actual motion and loop/root-motion contracts, an actual skinned LOD1, collision primitives, and PBR surfaces;
- 3D print requires a closed positive-volume mesh, explicit millimetres, an IR-declared minimum feature and global `2V/A` screening value of at least 0.8 mm, a completed bounded inward-ray local wall audit with every sampled wall at least 0.8 mm, and measured generic 45° overhang area. The default local audit caps work before large allocations at 256 meshes and 500,000 collected triangles, then at 96 rays per mesh and 24 million triangle tests; missing hits, zero-volume components, and exhausted budgets block release. Printer-specific orientation and support generation remain downstream process checks.

A browser proof requires the viewer to export and reopen the actual GLB. The verifier waits for asynchronous reference projection, then binds the receipt to the normalized input fingerprint, the exact pre-export build fingerprint, the scene-fingerprint revision, and the exact scene fingerprint after deterministic normal/tangent preparation. Scene identity includes actual inspectable texture pixels, dimensions, colour space, sampler state, and UV transforms. All values are compared with a current repeated build; hexadecimal shape alone is not evidence. Duplicate asset ids, a dirty browser console, more than 0.1 mm bounds drift, less than 95% named-node coverage, missing morph-payload parity, missing texture-payload parity, or uninspectable texture pixels fail closed. A fixed score, stale compiler/fingerprint revision, stale input/build/prepared-scene proof, or download click is not evidence.

It does not convert triangle count into a beauty score. Reference fidelity needs the same admitted images and camera calibration. Morphloom computes same-canvas reference/render silhouette IoU, interior pixel similarity, feature-region scores, material response, and frame fingerprints. The strict multi-view path downsamples the complete shared canvas and never fits each foreground independently, so offset, scale, framing, pose, and proportion errors remain measurable. A winner claim is refused unless both engines use the locked identical input, matched calibrated cameras, one canonical canvas/pixel-ratio/color/tone/light protocol, actual browser WebGL captures with hash-bound receipts, declared critical regions, and at least five unique blind raters with balanced presentation order. Automatic metrics alone may report a lead, never superiority. Capture sets run through `npm run benchmark:visual-set`; the manifest format and fail-closed release flag are documented in [`../docs/VISUAL_CAPTURE_SET.md`](../docs/VISUAL_CAPTURE_SET.md). See also [`../docs/COMPETITIVE_BENCHMARK.md`](../docs/COMPETITIVE_BENCHMARK.md).

The gate also refuses reused reference or render bytes, a structural scene fingerprint that changes across views, a screenshot hash passed off as structural scene evidence, a reused or hash-mismatched browser capture receipt, a receipt whose canvas or render protocol differs, evidence paths escaping the manifest directory, different feature rectangles between candidates, renamed copies of one rectangle, blank/tiny foreground evidence, byte-identical reference/render pixels, and a high average that hides a failed calibrated view. Every calibrated view for one candidate must come from the same independently fingerprinted compiled scene. Industrial design needs at least two distinct views and three distinct, identical critical regions per view; architecture, character, and surface cases require their domain minimums. `talon-visual-broadside-latest.json` is intentionally `unproven`: its one real broadside capture is useful regression evidence but cannot satisfy the two-view and blind-panel claim contract.

`npm run benchmark:neutral-render` removes viewer composition as a confounder by importing an actual GLB into Blender 5.2.1 LTS, fitting the broadside envelope to exactly 2.0 units, and using a locked Eevee camera/light/color-management protocol. `npm run benchmark:neutral-audit` recalculates the GLB and PNG SHA-256 values, confines artifacts beside each receipt, requires identical settings for both candidates, and requires one stable GLB with distinct front/rear/iso renders. Passing this audit proves fair render conditions only; `talon-neutral-front-latest.json` remains `unproven` without matched multi-view references and blind ratings.

`npm run benchmark:static-delivery` reads the source triangle count and browser loader receipts from the real downloaded asset pack, then binds its OBJ/STL/PLY/USDZ bytes to SHA-256 values, the current GLB compiler revision, static-delivery revision, and asset id. Packed bytes must exactly match the files independently imported by Blender 5.2.1. OBJ/PLY coordinates remain metres; STL coordinates are multiplied by 1,000 and explicitly contracted as millimetres. All three formats need exact triangle parity and at most 0.1 mm unit-normalized envelope drift. Apple's `usdchecker` must accept the repaired USDZ. This proves static-mesh and Apple AR handoff only. It does not turn OBJ/STL into STEP/BREP or preserve PBR, rigging, and animation outside GLB.

A digitally connected harness is not automatically production-ready. Any `bench-required` conductor, pending bench check, or inferred component keeps the physical-release flag false even when every 3D endpoint is snapped.

The Spider-Man single-image case therefore records two separate results: the compiled asset can pass closed-topology and editable-part gates while the one-view likeness gate remains blocked. `gamePrevisBaseReady` must never be presented as `productionLikenessReady`.

The Galaxy Z Fold8 exterior case records Samsung's published folded and unfolded envelopes separately from the compiled camera-bump envelope. Official dimensions, screen ratios, camera count, material families, and accessory-placement drawing values are `datasheet`; unpublished ring diameters, button protrusion, port pitch, and crease response remain `estimated` or `inferred`. Its exterior-only scope must not be reported as an internal engineering model.

When a new baseline is added, store its public URL, version, visible metrics, and the date observed. Never copy a proprietary asset into this directory.

`talon-same-reference-latest.json` is the first real same-input render case. It keeps the public URL and measured delivery facts only; the third-party reference bitmap and competitor render are not redistributed. The result deliberately separates photographic likeness from editable delivery quality.

`asphalt-reference-latest.json` records the local-photo surface path without redistributing the bitmap. The gate binds the image fingerprint to the embedded fine/medium/coarse-band height field, projected albedo, browser-derived normal/roughness maps, closed topology, and GLB reopen result. The material comparator separately measures scale balance, gradient entropy, periodicity, and irregularity so a repeating stripe pattern cannot impersonate crushed aggregate. Its 100% model-completeness score means that declared visual-material checks passed; the separate source-confidence score remains below production measurement confidence because one photograph cannot determine absolute height.
